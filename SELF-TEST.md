# Самопроверка (ru-сборка)

Всё, что ниже, прогнано на этой машине при локализации. Команды — из каталога `ph/`.

## 1. Сборка

```bash
node scripts/build-client.mjs
# build-client: модулей 14 -> lib/client.js (~240 КБ)
```

## 2. Тесты

```bash
node --test --test-isolation=none test/*.test.js
# tests 107 | pass 107 | fail 0
```

`--test-isolation=none` нужен из-за песочницы: обычный `node --test` запускает каждый файл
дочерним процессом и падает на `spawn EPERM` (нельзя открыть пайпы). В обычном окружении
достаточно `npm test`.

Что покрывают тесты (все проверки текстов переведены на русский):

- `analysis` — календарные дни, риски, сортировка, сводки.
- `views` / `insights` — модули, умные виды, KPI, распределения, календарь, таймлайн, корзины задач.
- `aiplan` — разбор дат («в следующую пятницу» → +8 дней от четверга, «послезавтра», «конец месяца»,
  «3 ноября», «+3 дня»), поиск проектов по id/имени/вхождению, неоднозначность, нормализация плана,
  предпросмотр, применение, локальные правила на русских формулировках.
- `query` — «что сдаём на этой неделе», «где риски», «что на контроле», «просрочено», блокеры,
  частичный промах («посмотри ту штуку») и подсказка.
- `prompt` — брифы проектов и четыре типа документов (недельный отчёт, статус, риски, протокол).
- `server` — маршруты `/meta`, `/state`, `/ai`, откат к правилам при недоступной модели.
- `store` — атомарная запись, версии, нормализация мусора.
- `client-bundle` — рендер панели в React: вкладки, KPI, графики, пустые состояния, ошибки.

## 4. Сборка tarball и установка

```bash
npm pack --pack-destination ..        # dsh-workbench-project-console-1.0.3.tgz, 14 файлов
```

Установка в профиль `web` выполнена инструментом плагинов DSH; результат:

```
generation-install: promoted to dsh-workbench-project-console+1.0.3+5afcfb5cb1ca
```

Проверка содержимого установленной копии:

```powershell
$p = "$env:DSH_HOME\profiles\.generations\live\dsh-workbench-project-console+1.0.3+5afcfb5cb1ca\node_modules\dsh-workbench-project-console"
Select-String -Path "$p\lib\client.js" -Pattern 'Пульт проектов' -SimpleMatch | Measure-Object
# Count: 3
```

## 5. Проверка живого интерфейса

```bash
node tools/verify-live.mjs     # из корня воркспейса
```

Скрипт берёт токен из `harness.log`, получает cookie, вытаскивает из загрузочного манифеста
страницы combo-URL с `dsh-workbench-project-console/client.js` и проверяет в нём русские строки.

До перезапуска Harness скрипт показывает старую сборку (`Русский интерфейс: НЕТ`) — хост держит
клиентский модуль в памяти с момента старта. После **Harness → Перезапустить** и обновления
страницы должно быть `ДА` и «Остатки китайского: нет».

## 6. Ручные проверки после перезапуска

1. Переключатель режимов слева → «Пульт проектов» открывается без ошибок в консоли.
2. Обзор: 6 KPI, кольцо рисков, стек модулей, гистограмма, рейтинг ответственных.
3. Вкладки «По модулям / По статусам / Список / Календарь / Таймлайн / На контроле» переключаются.
4. «Спросить» → «что сдаём на этой неделе?» отвечает по демо-данным.
5. «AI-заполнение» → «Перенеси дедлайн проекта «Переработка сервиса расчётов» на следующую пятницу,
   прогресс — 80%» → предпросмотр, подтверждение, запись, «Отменить».
