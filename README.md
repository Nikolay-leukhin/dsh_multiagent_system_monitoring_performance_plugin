# Пульт проектов (dsh-workbench-project-console)

Локальный воркбенч для DSH Desktop: в одном месте лежат все рабочие проекты, текущие задачи
и мелкие проекты, которые идут параллельно. По модулям видно статус, прогресс, задачи на контроле
и риск по дедлайнам; карточку можно открыть, задать вопрос одной фразой или попросить Agent
проанализировать записи и собрать черновик отчёта.

Воркбенч работает только локально и не публикуется в маркетплейс.

> Это русская локализация [OliverLiy/projectHub](https://github.com/OliverLiy/projectHub) (MIT).
> Переведены интерфейс, промпты, демо-данные и шаблоны документов; правила разбора русского языка
> переписаны в `src/shared/aiplan.js` и `src/shared/query.js`.

## Что решает

- Проектов слишком много, они размазаны по голове и нескольким таблицам — нет места, где сразу
  видно «кто идёт, что горит, что вот-вот сдавать».
- Задачи теряются, особенно когда параллельно идёт десяток проектов.
- Каждый раз для недельного отчёта, статуса или списка рисков приходится заново перелистывать записи.

## Основной сценарий

1. **Вход**: в переключателе режимов сверху боковой панели выберите «Пульт проектов». Сессии и рабочей
   области может не быть — страница открывается сразу.
2. **Доска**: под верхней панелью 7 вкладок, слева — навигация по модулям («Все» / «Рабочие проекты» /
   «Текущие задачи» / «Другие проекты» и ваши собственные модули) со счётчиками и числом рисков,
   а также «Умные виды»: требуют внимания / просрочено / дедлайн на неделе / на контроле / завершено.
   Все вкладки подчиняются фильтру слева.

   | Вкладка | Разрез | Содержимое |
   |---|---|---|
   | Обзор | статистика | 6 KPI (всего проектов / требуют внимания / на контроле / дедлайн на неделе / средний прогресс / без срока), вывод одной фразой, «Спросить», **кольцевая диаграмма рисков**, **стек по нагрузке модулей**, **гистограмма прогресса**, **рейтинг ответственных**, срочно требует внимания, дедлайн на неделе |
   | По модулям | модуль | стена карточек по модулям; в заголовке — проектов / требуют внимания / на контроле / средний прогресс |
   | По статусам | статус | колонки «В работе / Не начат / Блокер / На паузе / Завершён», внутри — сортировка по риску |
   | Список | детали | компактная таблица: проект / модуль / статус / прогресс / дедлайн / осталось / риск / на контроле |
   | Календарь | по дням | месячная сетка, дедлайны и задачи попадают в свои клетки (с цветом риска), можно листать месяцы, вернуться к «сегодня», открыть день и отметить задачу выполненной |
   | Таймлайн | интервал | полосы в стиле Ганта, по строке на проект, по датам начала и дедлайна, цвет по риску, шкала недель и вертикаль «сегодня» |
   | На контроле | действия | все задачи по корзинам: просрочено / срок сегодня / на этой неделе / позже / без срока — с отметкой выполнения на месте |

3. **Клик**: карточка, полоса таймлайна, строка списка или имя проекта в календаре открывают справа
   карточку: сетка ключевых полей, полоса риска с обоснованием, описание и теги, записи о прогрессе
   (добавление по типу, цветная лента), список задач, кнопки AI-помощника.
4. **Спросить**: введите «что сдаём на этой неделе?», «где риски?», «что у меня на контроле?» — панель
   отвечает по локальным данным; проекты из ответа можно открыть.
5. **Отдать Agent**: в карточке или в обзоре нажмите «Проанализируй прогресс / Недельный отчёт /
   Отчёт о статусе / Список рисков / Каркас протокола встречи» — панель соберёт промпт или черновик
   документа, скопирует одной кнопкой в соседнюю сессию или скачает как `.md`.

**Успешное состояние**: проект помечен «Завершён», либо изменения записаны (справа сверху
«Сохранено · версия N»).
**Восстановление после ошибки**: при неудачном сохранении панель откатывается к последним успешным
данным и показывает причину; конфликт версий (другое окно уже изменило файл) предлагает
«Перезагрузить»; повреждённый файл данных не перезаписывается.

## Демо-данные

При первом входе (документ пуст и демо ещё не генерировались) автоматически создаются 12 проектов
по модулям — типичная работа бэкенд/фулстек-инженера, чтобы доска не была пустой:

| Модуль | Примеры |
|---|---|
| Рабочие проекты | Переработка сервиса расчётов, Подключение домена заказов к платформе данных, Ускорение первого экрана мобильного клиента, Запуск платформы канареечных релизов |
| Текущие задачи | Подготовка доклада «Разбор инцидентов на проде», Квартальный техотчёт Q3, Дежурство по алертам и разбор инцидентов, Обновление зависимостей и разбор техдолга |
| Другие проекты | Свой мини-инструмент мониторинга, Ведение issue и PR в open-source, Заметки и блог, Прототип мини-приложения |

Покрытие: просрочено 2, срочно 3, отставание 2, блокер 1, завершён 1, в норме 3, плюс 13 открытых
задач и несколько записей о прогрессе; у каждой записи тег «Пример». Внизу боковой панели
«Демо-данные» создают ещё одну порцию, «Очистить» удаляет всё (с подтверждением).

## AI-заполнение (естественный язык → план изменений)

Кнопка «AI-заполнение» в верхней панели: одной фразой скажите, что сделать, — воркбенч определит
**добавление / изменение / удаление / запрос** и покажет читаемый список изменений. **Добавление,
изменение и удаление сначала требуют подтверждения**; запрос только отвечает и данные не меняет.

- Инструкция уходит в LLM, зарегистрированную хостом (по умолчанию provider/model из `agentDefaultModel`);
  модель только «переводит», а **проверка, сопоставление проектов, разбор дат, предпросмотр и запись**
  делаются чистыми функциями воркбенча — если модель ошибётся, данные не изменятся.
- Если модель недоступна (нет сервиса llm, не задана модель по умолчанию, таймаут, ответ не JSON) —
  включается **локальный разбор правилами**; в интерфейсе указано, что сработало: «Разбор моделью»
  или «Локальный разбор».
- Поддерживаются: новый проект, изменение проекта (название/модуль/статус/ответственный/даты/прогресс/
  описание/ссылка), удаление проекта, новая задача, закрытие задачи, запись о прогрессе; до 20 действий за раз.
- Ненайденные и неоднозначные проекты пропускаются, причины перечисляются в окне подтверждения.
- После выполнения сверху остаётся полоса «Отменить» — один клик возвращает состояние до применения.

Примеры:
- «Перенеси дедлайн проекта «Переработка сервиса расчётов» на следующую пятницу, прогресс — 80%»
- «Новый проект: пилот service mesh, в «Рабочие проекты», дедлайн — конец месяца»
- «К докладу «Разбор инцидентов на проде» добавь задачу: до пятницы провести прогон»
- «Удали прототип мини-приложения»
- «Что сдаём на этой неделе?»

> После изменения серверной точки входа нужно перезапустить Harness (меню приложения
> **Harness → Перезапустить** / <kbd>⌘⇧R</kbd>); до перезапуска «Разобрать» сообщит, что сервер ещё
> не загрузил API AI-разбора.

## Выпуск новой версии

Адрес в маркете фиксированный:
`https://github.com/OliverLiy/projectHub/releases/latest/download/dsh-workbench-project-console.tgz`,
поэтому для релиза не нужен PR в каталог:

1. измените `version` в `package.json` (полный SemVer);
2. `pnpm verify && pnpm pack`;
3. создайте Release на GitHub и загрузите пакет **с фиксированным именем**
   `dsh-workbench-project-console.tgz` (без версии в имени файла);
4. каталог пересобирает индекс раз в день и сам подхватит новую версию и контрольную сумму.

В каталоге версия не указывается — её определяет `package.json` внутри пакета.

## Где лежат данные

Данные проектов хранятся в каталоге данных DSH:

```
$DSH_HOME/project-console/state.json
# на этой машине: %APPDATA%\dsh-desktop\harness\project-console\state.json
```

- Запись атомарная (временный файл + rename) и с номером версии для обнаружения гонок.
- Удаление воркбенча **не** удаляет этот каталог: после переустановки данные на месте.
- Хотите начать с нуля — уберите или удалите этот файл.

## Как считается риск по срокам

Сравнение идёт по локальному календарному дню, уровни от высокого к низкому:

| Уровень | Условие |
|---|---|
| Просрочено | сегодня позже дедлайна |
| Блокер | статус «Блокер» |
| Срочно | до дедлайна ≤ 3 дней |
| Отставание | прошло X% срока, а прогресс заметно отстаёт (доля времени − прогресс ≥ 30%) |
| Скоро дедлайн | до дедлайна ≤ 7 дней |
| Без срока | дедлайн не заполнен |
| В норме | остальные проекты в работе |
| Завершён | статус «Завершён» |

## Установка (локально)

Пакет собран по спецификации; в `web`-профиль он ставится штатным способом установки плагинов
DSH Desktop:

```bash
pnpm pack                      # получаем dsh-workbench-project-console-1.0.3.tgz
dsh plugin --profile web add "$PWD/dsh-workbench-project-console-1.0.3.tgz"
```

`dsh plugin` распаковывает пакет в профиль и добавляет его в `dsh.profile.bundles`, поэтому он
загружается как слой плагина. После установки перезапустите Harness (меню приложения
**Harness → Перезапустить**, или <kbd>⌘⇧R</kbd>), затем в «Управление воркбенчами / Установленные»
подтвердите запись и добавьте её.

При первом запуске также нужно включить в **Настройки → Общие** пункт «Включить воркбенчи»
(это переключатель хоста, воркбенч не может включить его за вас).

## Разработка

```bash
pnpm install
pnpm build      # собирает src/ в однофайловый клиентский модуль lib/client.js
pnpm test       # unit и интеграционные тесты на node:test
pnpm check      # проверка формата пакета по разделу 3 спецификации
pnpm verify     # build + test + check
```

### Ограничения клиентской сборки

Desktop не собирает клиент за вас: `lib/client.js` должен быть готовым однофайловым модулем.
`scripts/build-client.mjs` поддерживает лишь маленькое подмножество синтаксиса: однострочные
`import`/`export` в нулевой колонке, остальное (включая CSS-шаблонные строки) переносится как есть.
Модули с относительными путями встраиваются; «голые» имена пакетов (`react`) отдаются в `require`
загрузчика модулей — это общая база хоста. Неподдерживаемый синтаксис падает на сборке, а не даёт
битый пакет.

## Границы интерфейса

- Панель регистрируется как **встроенная бизнес-панель слева** (`embedded: true` +
  `businessSide: 'left'` + ширина 0.68); первый дочерний элемент корня — семантический `<header>`:
  это структура из документации хоста, при свёрнутом сайдбаре macOS хост резервирует под кнопки окна
  `--dsh-frame-leading-clearance` (на этой машине работает 160px).
- Ширина панели ограничена хостом: только левые 68% основной области; нативная сессия остаётся
  справа, общие входы (сайдбар, переключатель режимов, «Управление воркбенчами», настройки) — за хостом.
- `customFrame` не используется (он забирает у хоста вход «Создать рабочую область и начать диалог /
  новая сессия в этой области», и его пришлось бы делать заново), свой чат-интерфейс тоже не строится:
  нативную сессию размещает хост.
- Стили по возможности переиспользуют дизайн-токены хоста (`--dsw-*`: цвета, радиусы, шрифты)
  и следуют теме Desktop; раскладка подстраивается container queries по ширине панели, а не по вьюпорту.
- Не создаёт сессии, не переписывает их принадлежность и не трогает рабочие области: все действия,
  зависящие от сессии, заканчиваются копированием промпта в соседнюю сессию.
- Доступность с клавиатуры: всё — нативные `button`/`input` с видимым фокусом.
